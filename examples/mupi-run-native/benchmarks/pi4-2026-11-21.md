# MuPi Run Native – Raspberry Pi 4 GPU performance, 21.11.2026

**Hardware:** Box 83, Raspberry Pi 4 Model B Rev 1.1, 955 MiB available RAM,
800×480 logical Qt Window, Pi OS / Mesa V3D 4.2.14.0, OpenGL ES 3.1.
The production MuPiBox UI remained active on EGLFS and retained its physical
screen. Native QML was run on a *separate, headless* 800×480 Weston/Wayland
OpenGL compositor (`/dev/dri/renderD128`). The existing NG box version at
initial measurement was alpha.67. During later cleanup, the box showed
alpha.71 and the temporary test folders had been cleared by external action;
we did not deploy NG or change production configuration.

**Audio:** Fully muted, **0 %**. The native QML prototype has no active
sound output; there were **no audio sample/music requests** to the real
box audio backend, and no system volume changes. This is below the user's
explicit 5 % ceiling.

## Comparison to the existing Web implementation

Historic Web MuPi Run **0.8.4** tests on the same Pi 4, documented in
[`examples/mupi-run/benchmarks/pi4-2026-11-20.md`](../../mupi-run/benchmarks/pi4-2026-11-20.md),
showed **27.14–30.15 FPS**, p95 **44–49 ms**, peak tested PSS for
WebEngine/Chromium/host **384–394 MiB**, CPU roughly 100–125% of one core.
Those historical tests used the original web game's complete renderer and
music/mixer, but a different renderer stack and older game release.

**Interpretation:** This Qt prototype is roughly in the same **28–30 FPS
range** as optimized Web 0.8.4, rather than showing a proven native FPS win.
However the process-set memory footprint appears **substantially smaller**
(~165 MiB Qt+Weston versus ~384–394 MiB Qt+Chromium+host). This is an
*indicative, non-matched comparison*: Web engine/host measured broader
components and included game audio; the native code omits full Web drawing
fidelity and actual audio/SDK integration. No scientific 1:1 claim is
supported until a complete Web 0.8.7 replay is obtained with matching
process accounting and scenes.

## Performance change during implementation

The first QML renderer updated `Image.sourceClipRect` to extract each sprite
frame directly from an atlas. On the Pi4 this caused repeated work in the
image pipeline and only around **19–23 FPS** in several short trials,
including p95 up to 100 ms. Switching to a **persistent atlas image clipped
by a lightweight `Item`** improved the renderer: a 6.7-second GPU trial
then measured **29.16 scene FPS, 37.79 window FPS, frame p95 37 ms, p99 45
ms**. The 15/45-second trials above are after that optimization.

The native renderer uses the exact original fixed-step 60 Hz game logic but
**approximates** the original CPU-perspective road into 12 precomputed
texture phases per terrain, displays butterflies and gold notes with simple
Qt glyphs rather than exact canvas sprites, and has a simplified HUD.
This affects workload and visual fidelity; therefore it does **not**
validate pixel-perfect equivalence. 24 running + 35 jump + 35 duck frames
per respective original atlas action are represented without resampling the
source frame data. Collision, spawn and note rules are unchanged.

## Safety and outstanding work

- GPU V3D context confirmed from both Weston and Qt `QSG_INFO`; test output
  was headless. The real physical DSI panel, touch, key/controller latency,
  compositor lifecycle, music playback, sound under 5 %, and host SDK were
  **not** tested in this prototype.
- No `qtquick-scene` third-party package includes executable QML or JS.
  NG alpha.70 still *correctly rejects* that. This experiment is trusted
  local QML source, not a production community app installation.
- Automatic all-terrain test is a surrogate for physical player inputs.
  The JS physics parity test compares every state against original Web
  `logic.js` under 4 seeds at 60 Hz. Real hardware input still needs QA.
- Attempts to construct a matched Web 0.8.7 benchmark in the same private
  compositor could not complete: the first cross-compiled Go test host had
  SQLite CGO disabled; a corrected ARM64 binary was built, but the Pi `/tmp`
  benchmark working directories were unexpectedly removed before retry.
  **No Web 0.8.7 A/B numbers are claimed.**
- Existing MuPiBox services remained `active`; temporary GPU test packages
  were extracted to `/tmp`, no production packages or updates were installed
  in this test, and removable empty mountpoint directories were cleaned.
